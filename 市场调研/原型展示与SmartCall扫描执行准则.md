## 1. 当前总原则

本项目分成两条并行路线：

```text
原型展示线：先证明业务流程和产品价值
技术核验线：先核验 SmartCall 是否适合作为生产底座
```

两条路线不能混淆：

- 原型中的模拟通话、模拟评分和模拟报表，不得描述成生产能力。
- SmartCall README 中的功能描述，不得直接当作已经验收的功能。
- 业务需求文档先冻结，技术核验结果以附录形式补充。
- 在没有名单来源和合法联系依据的情况下，不能进行真实生产外呼。
- 下周二展示优先保证业务闭环，不把时间耗在运营商、真实号码和复杂本地语音部署上。

## 2. 下周二展示目标

展示对象应该能看懂以下业务闭环：

```text
潜客名单导入
    -> 来源/授权审核
    -> 创建外呼任务
    -> AI 首次沟通
    -> 意向判定与分组
    -> 高意向转真人红娘
    -> 红娘跟进
    -> 报表和质检
```

本次展示的定位：

> “AI 红娘潜客筛选与人工跟进业务原型”，不是“已经完成生产部署的批量外呼系统”。

### 2.1 原型必须展示的页面

1. **潜客名单中心**
   - CRM 同步和 CSV/Excel 导入入口。
   - 来源、来源说明、授权状态、审核状态。
   - 待核验、可外呼、黑名单和退订标签。
   - 城市、来源、性别/年龄段、意向等业务标签。

2. **外呼任务创建**
   - 选择潜客分组。
   - 选择 AI 红娘、话术和知识库。
   - 设置外呼时间、并发、重拨、频控和转人工规则。
   - 启动前展示有效名单数和预计尝试量。

3. **实时外呼看板**
   - 总名单、待拨、拨打中、已接通、有效对话。
   - 高/中/低意向、转人工、失败和退订。
   - 当前并发、异常、估算用量和成本。

4. **AI 通话详情**
   - 对话转写时间线。
   - AI 摘要和结构化字段。
   - 意向分数、意向分组、命中规则。
   - 转人工按钮和建议下一步。

5. **红娘工作台**
   - 高意向待办队列。
   - 客户资料、AI 摘要、关键回答和建议话术。
   - 接收、分配、回访时间、跟进结果和备注。

6. **报表和 AI 质检**
   - 潜客漏斗。
   - 意向分布和转人工率。
   - 红娘跟进结果。
   - 开场、必问项、敏感词、拒绝处理和结束语质检。

| 项目 | 初步结果 | 证据位置 |

| 数据库 | MySQL，包含核心、业务和 Asterisk SQL | `sql/`、`README.md` |

### 3.3 已发现的配置风险

`smart-boot/src/main/resources/application.yml` 中存在默认配置示例：

```text
235: DB_MASTER_PASSWORD:12345678
258: DB_ASTERISK_PASSWORD:12345678
268: ASTERISK_AMI_USERNAME:admin
269: ASTERISK_AMI_PASSWORD:a1b2c3
406: MAXKB_USERNAME:admin
408: MAXKB_PASSWORD:MaxKB@123...
```

这些内容目前只能视为开发默认值，不能直接用于任何公网或客户生产环境。上线前必须：

- 使用环境变量或密钥管理系统注入真实凭据。
- 修改数据库、Asterisk AMI、MaxKB 和所有默认管理账号。
- 禁止把 `.env`、API Key、录音地址和生产配置提交到 Git。
- 检查日志、异常栈和前端配置是否泄露密钥。
- 检查 Asterisk AMI、AGI、数据库和管理后台是否暴露公网。

## 4. SmartCall 扫描准则

### 4.1 扫描顺序

按以下顺序执行，不要一开始通读全部源码：

1. **来源与许可证**
   - 记录源码来源、下载日期、版本/commit。
   - 阅读 `LICENSE`、README 和第三方依赖许可证。
   - 确认交付时保留 Apache 2.0、版权和 NOTICE 信息。

2. **目录和模块地图**
   - `smart-aster`：呼叫、IVR、ASR/TTS、AI 节点。
   - `smart-maxkb`：知识库适配。
   - `smart-boot`：单体启动入口。
   - `smart-upms`、`smart-auth`、`smart-gateway`：权限、认证和网关。
   - `script`：Docker、Asterisk、Nacos、ELK 等部署资源。
   - `sql`：初始化和升级脚本。

3. **配置和安全扫描**
   - 搜索默认密码、API Key、Token、私钥、外部回调和公网地址。
   - 检查默认账号、CORS、管理端口、Asterisk AMI/AGI 暴露情况。
   - 检查录音下载接口、文件路径和权限控制。
   - 检查用户输入进入脚本、SpEL、Groovy/JavaScript 执行节点的边界。

4. **编译和最小启动**
   - 先尝试单体模式，不先搭完整微服务栈。
   - 记录 JDK、Maven、Docker、MySQL、Redis、Asterisk 版本。
   - 记录编译错误、缺失依赖、镜像下载和数据库初始化问题。

5. **功能核验**
   - 登录后台。
   - 创建一个机器人/流程。
   - 建立一个测试坐席或 SIP 端点。
   - 验证拨号、接通、录音、转写、AI 回复、挂断。
   - 验证外呼任务、暂停/恢复、重拨、去重和并发限制。
   - 验证转人工时能否传递摘要和客户信息。

6. **结果归档**
   - 每项结论只能写“已验证”“部分验证”“未验证”或“失败”。
   - 保存命令、日志、截图、配置版本和测试日期。
   - 不把 README 的“支持”直接改写成“已验收”。

### 4.2 必须回答的技术问题

| 编号 | 问题 | 通过标准 |
|---|---|---|
| S-001 | 能否用单体模式启动 | 在干净环境完成启动并能登录 |
| S-002 | Asterisk 是否能正常启动 | 容器/服务启动，无关键错误 |
| S-003 | 是否能连接 MySQL 和 Redis | 初始化 SQL 成功，业务请求正常 |

| S-006 | 是否能录音并查询 | 录音与 call_id、通话记录正确关联 |
| S-007 | 是否支持 ASR/TTS 流程 | 完成一轮语音输入和播报 |
| S-008 | 是否支持用户打断 | 用户讲话后停止当前播放 |
| S-009 | 是否支持转人工 | 人工坐席可接收，能看到必要上下文 |

## 5. 原型和生产的分界

### 5.1 原型可以模拟的内容

- 模拟拨打状态：待拨、拨打中、接通、完成、失败。
- 模拟对话转写和 AI 摘要。
- 模拟意向评分、标签和分组。
- 模拟转人工和红娘跟进。
- 模拟报表和成本数据。
- 使用脱敏或虚构的潜客数据。

### 5.2 必须真实验证后才能写入生产能力的内容

- 真实运营商/CPaaS/SIP 线路。
- 真实手机号批量外呼。
- 真实并发上限和接通率。
- ASR/TTS 实时延迟和打断效果。
- 录音保存、下载和删除。
- 运营商投诉、退订和黑名单处理。
- CRM/ERP 真实回写。

以下情况不得直接加入原型或生产：

## 8. 当前结论

SmartCall 可以继续作为第一阶段技术核验对象，初步符合“Java + Asterisk/PJSIP + AI + MaxKB + 外呼扩展基础”的方向；但它目前只是源码快照，尚未完成编译、启动、真实拨号、录音、打断、转人工和并发 POC。

下周二的交付重点是业务原型，不是生产系统。技术核验结果必须按本准则归档，后续再决定是否继续使用 SmartCall、是否补写二次开发需求，以及是否接入真实通信资源。
